# 移动教务运行边界与回归清单

本文件记录移动教务链路的当前完成状态。该链路已经是 `XKE.DotNet8` 当前主数据源，但仍需要在后续后端重构中保持回归。

## 已完成的运行模型

- 移动教务负责身份和课表数据，不等同于传统 Web 教务系统。
- 首次初始化必须真实移动教务认证成功，并拿到可用 profile 与非空课表。
- 已有本地凭据时，`/api/auth/login` 只做本地密码校验和本地数据完整性检查。
- `/api/auth/session` 与 `/api/auth/trusted-login` 只恢复本地工作状态，不自动访问远端。
- `/api/auth/connect` 是“重新验证移动教务数据源状态”，不是传统教务验证码连接。
- `/api/schedule/preferred` 始终是移动教务课表刷新入口，不要求先 connect。

## 移动教务认证材料

- 登录顺序固定为 `getKey -> AES 密文 -> login -> token`。
- AES 密文由 `MobileJwLoginClient` 生成，保存在 `StoredCredentialDocument.MobileJw`。
- `MobileJw` 字段包含 `encrypted_password`、`generated_at`、`expires_at`，通过凭据 store 的 DPAPI 文件保存。
- 密文 TTL 为 1 小时。
- TTL 内优先复用密文；若 login 失败，刷新 `getKey` 后重试一次。
- TTL 过期后不探测旧密文，直接重新 `getKey` 生成新密文。
- token 只作为当前进程内远端会话材料；宿主重启后 `connected=false` 是正常状态。

## 数据落库边界

- 首次初始化成功后必须至少落库：
  - profile：包含 `student_id` 和 `name`
  - credentials：包含本地密码、trusted token、移动教务加密材料
  - session：当前本地工作区会话
  - schedule：至少一条可归一化课程行
- 移动教务课表同时保存 `mobile_schedule.json` 和 `mobile_schedule.csv`；前端渲染仍以归一化 JSON 为准，CSV 只作为备份/导出准备数据，不包含 `source_key`、`source_type` 等内部来源字段。
- 课表初始化失败时首登失败，并回滚本次半初始化状态。
- Notice 可降级，不作为首登成功的硬门槛。
- 本地 profile 或 schedule 缺失时，已有本地凭据登录也不得进入工作区。

## 与传统教务的隔离

- 不把移动 token 当成传统 Web Cookie。
- 不把 `/api/schedule/preferred` 改成传统 Cookie 课表入口。
- 不把传统验证码 UI 放回主登录卡片。
- 不让传统教务 `jw_schedule` 反向覆盖移动教务主课表；两个来源各自保留同列 CSV 备份，前端仍按用户选择读取对应 JSON。
- Course 真实连接、验证码、OCR、Cookie 课表、抢课全部属于后置链路。
- 传统教务资料进入 `notes/sensitive-index/教务系统/`，不放入本目录。

## 开发回归要求

- 修改 `AuthService`、`ScheduleService`、`MobileJwLoginClient`、`NativeJwAuthClient`、`NativeJwScheduleClient` 后，必须复核本文件。
- 自动化测试至少覆盖：
  - 首登成功返回 profile 和非空 `cached_schedule`
  - 首登 token/profile/schedule 任一失败时回滚
  - 已有本地凭据登录不调用远端
  - session/trusted-login 恢复 `connected=false`
  - `/api/schedule/preferred` 可基于本地凭据刷新移动课表
  - 密文 TTL 内复用、失败刷新、过期刷新
- 真实验证使用 `tools/mobile-real-smoke.mjs`，默认交互输入密码并保留本地诊断目录。

## 文档维护要求

- 移动教务认证材料、TTL、接口语义或存储字段变化时，必须更新本文件与 `01_认证流程索引.md`。
- 如果传统教务计划变化，只更新 `../教务系统/` 与 `../../future-plans/`，不要把传统教务状态写成本目录主线。
