# 移动教务认证流程索引

本文件用于指导移动教务链路回归、维护和小范围补充开发。传统 Web 教务系统的验证码、Cookie、HTML 课表和抢课资料不写在这里。

## 目标闭环

移动教务链路应保持以下闭环稳定：

1. `POST /api/auth/login` 首次初始化账号
2. 移动教务完成 `getKey -> AES 密文 -> login -> token`
3. 成功后写入本地 profile、credentials、session、schedule
4. `POST /api/auth/connect` 可在本地 session 下重新验证移动教务数据源
5. `GET /api/auth/session` 可恢复本地 session，不访问远端
6. `POST /api/schedule/preferred` 可基于本地凭据刷新移动课表
7. `GET /api/schedule/local` 可读取本地课表缓存

## 接口行为

### `POST /api/auth/login`

- 请求字段：`user`、`password`、`prelogin_mode`
- `prelogin_mode`：`capture` 或 `coded`
- 首次本地无凭据：
  - 连接移动教务
  - 拉取学生 profile
  - 拉取首份移动课表
  - 写入本地凭据、session 和课表缓存
  - 返回 `connected=true`
- 本地已有凭据：
  - 只做本地校验
  - 不主动连接远端
  - 返回 `connected=false`
  - 本地 profile 或课表缓存不完整时失败，不进入工作区

### `POST /api/auth/trusted-login`

- 请求字段：`user`、`trusted_login_token`、`prelogin_mode`
- 行为：只做本地可信恢复
- 敏感点：trusted login token
- 规则：真实 token 不写入文档、测试或 fixture

### `POST /api/auth/connect`

- 前提：已有本地 session
- 行为：重新连接移动教务并刷新移动端连接状态
- 成功语义：`connected=true`
- 失败语义：返回认证或冲突错误，不清空本地可恢复资料

### `GET /api/auth/session`

- 行为：只恢复本地 session
- 远端行为：不连接移动教务
- 常见语义：`connected=false`

### `POST /api/schedule/preferred`

- 行为：刷新移动课表
- 前提：有本地 session 和本地凭据；不要求先调用 `/api/auth/connect`
- 成功语义：
  - `data_origin=live_fetch`
  - `source_type=mobile`
  - `cached=false`
- 认证材料：
  - 优先使用本地 DPAPI 凭据中的移动教务加密密文
  - TTL 未过期时复用密文；登录失败后刷新 `getKey` 并重试一次
  - TTL 过期后直接重新 `getKey` 生成新密文
- 传统教务开发期间不得改变该接口为 Cookie 课表入口

### `GET /api/schedule/local`

- 行为：读取本地课表缓存
- source 可用于选择来源
- 无缓存时返回未找到或当前项目约定错误

## 开发态 smoke 模板

以下命令只展示环境变量名和占位符，不写真实值。真实验证优先使用 Node smoke 的交互隐藏输入。

```powershell
node .\tools\mobile-real-smoke.mjs --user=<TEST_USER>
```

首次登录：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:<PORT>/api/auth/login" `
  -ContentType "application/json" `
  -Body '{"user":"<TEST_USER>","password":"<TEST_PASSWORD>","prelogin_mode":"capture"}'
```

刷新移动课表：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:<PORT>/api/schedule/preferred?session_id=<SESSION_ID>" `
  -ContentType "application/json" `
  -Body '{"mode":"current","manual_week":"","cookie_rq":"","term_label":"","academic_term":""}'
```

读取本地课表：

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://localhost:<PORT>/api/schedule/local?session_id=<SESSION_ID>&source=preferred"
```

## 回归矩阵

| 场景 | 触发方式 | 预期 |
| --- | --- | --- |
| 首次登录 | 本地无凭据调用 `/api/auth/login` | 返回 `connected=true`，写入本地资料和课表 |
| 本地登录 | 本地已有凭据调用 `/api/auth/login` | 返回 `connected=false`，不触发远端 |
| trusted 恢复成功 | 调用 `/api/auth/trusted-login` | 返回本地 session |
| trusted 恢复失败 | 使用错误 token | 返回 `401` |
| connect 成功 | 有效 session 调用 `/api/auth/connect` | 返回 `connected=true` |
| connect 失败 | 远端认证失败 | 返回错误，不清空本地缓存 |
| 移动课表刷新 | 调用 `/api/schedule/preferred` | 返回 `data_origin=live_fetch` |
| 密文 TTL 内刷新 | 有本地 `MobileJw` 且未过期 | 不重复 `getKey`，除非登录失败 |
| 密文 TTL 过期刷新 | 本地 `MobileJw` 已过期 | 直接重新 `getKey` 生成密文 |
| 运行期 token 丢失 | 宿主重启后刷新课表 | 可用本地凭据重新登录移动教务 |
| 本地课表读取 | 调用 `/api/schedule/local` | 返回 `data_origin=local_cache` 或等价本地缓存语义 |
| Cookie 入口隔离 | 调用 `/api/schedule/cookie` | 走传统教务入口，不影响移动课表 |
| 传统教务开发回归 | 修改 Cookie 课表后重跑移动链路 | `auth/login`、`auth/connect`、`schedule/preferred`、`schedule/local` 原行为不变 |

## 敏感点清单

- `user`、`password`：只能来自本地环境或测试配置
- `trusted_login_token`：禁止写入文档和测试源码
- 移动教务加密密文：保存在本机 DPAPI 凭据中，不写入文档、fixture 和日志样例
- 移动 token：仅作为运行期远端会话材料，不写入文档、fixture 和日志样例
- 原始移动响应：只能脱敏后进入 fixture
- 学生 profile：学号、姓名、学院、班级等需要脱敏

## 与传统教务的接口边界

- 移动课表来源使用移动教务 handshake，不依赖传统 Web Cookie
- 传统 Cookie 课表成功后应使用 `source_key=jw_schedule`、`source_type=jw`
- 移动课表成功后应保持移动来源语义，不改成 `jw_schedule`
- `ScheduleService.FetchPreferredAsync` 和 `FetchCookieAsync` 应保持职责分离
