# 教务系统接入资料索引

本文件用于指导传统 Web 教务系统 v1 接入开发。v1 只做“登录 + Cookie 课表”闭环，不实现真实抢课。

## 目标闭环

开发完成后，应能通过以下链路刷新传统教务课表：

1. 使用本地测试账号读取 `user`、`password`、`prelogin_mode`
2. 完成 SSO 预登录，准备登录页上下文、验证码/加密参数和初始会话
3. 提交 SSO 登录并通过 portal validate
4. 使用 SSO TGC 换取 JW ticket，并完成 JW bootstrap
5. 校验 `jw.hnsoftedu.com` 下 `/jsxsd` 路径的登录态 Cookie
6. 调用传统教务课表页面
7. 解析课表 HTML
8. 归一化为 `source_key=jw_schedule`、`source_type=jw`
9. 写入本地课表缓存
10. 通过 `/api/schedule/local?source=cookie` 或兼容 source 读取本地缓存

硬性边界：Cookie 不是登录入口。`/api/schedule/cookie` 不能接受外部 Cookie 作为登录态凭据，Cookie header 和 bundle 必须由完整预登录 + 登录 + JW bootstrap 流程生成。

## 旧实现深挖结论

旧传统教务核心链路不是“拿 Cookie 后直接请求课表”，而是：

```text
JwSsoClient.get_login_page
-> JwSsoClient.prepare_prelogin_bootstrap
-> JwSsoClient.fetch_captcha_text
-> JwSsoClient.login_portal
-> JwSsoClient.bootstrap_jw_session
-> JwSsoClient.fetch_schedule_html
```

关键结论：

- `get_login_page` 负责取得登录页 URL、`execution`、`login-croypto`、验证码地址和 redirect 信息。
- `prepare_prelogin_bootstrap` 是必经前置阶段；缺少该阶段时，即使后续拿到零散 Cookie，也不能视为已进入可用登录态。
- `capture` 模式依赖 `prelogin_capture.xml` 回放预登录请求。
- `coded` 模式通过动态预登录序列生成或刷新预登录录包。
- `login_portal` 成功后需要拿到 SSO 侧 TGC，再通过 portal validate 完成门户登录。
- `bootstrap_jw_session` 必须使用 SSO TGC 换取 JW ticket，并验证 JW 域名下 `/jsxsd` 路径的 `JSESSIONID`。
- `fetch_schedule_html` 只能在 JW bootstrap 成功后执行；如果响应变成登录页，应判定为 Cookie/JW session 失效。

## 旧流程阶段

### 1. 测试账号来源

- 环境变量名：`user`、`password`
- 可选环境变量名：`prelogin_mode`
- 默认登录模式：`capture`
- 可选登录模式：`capture`、`coded`
- 文档和测试代码中只允许写 `<TEST_USER>`、`<TEST_PASSWORD>` 这类占位符

### 2. SSO 预登录

- 旧实现位置：`Z:/XKE/core/jw_services.py`
- 重点对象：`JwSsoClient`、`LoginPageContext`、`RecordedPreloginRequest`
- 旧调用顺序：`get_login_page -> prepare_prelogin_bootstrap`
- 关注行为：
  - 获取登录页上下文
  - 读取 `execution` 与 `login-croypto`
  - 处理隐藏字段和动态预登录序列
  - 维护初始 Cookie
  - 准备验证码或加密登录所需参数
- `capture` 模式：
  - 从学生数据目录或回退路径读取 `prelogin_capture.xml`
  - 回放录包中的预登录请求
  - 缺少录包或录包不完整时，应返回可读错误
- `coded` 模式：
  - 动态生成预登录请求序列
  - 执行序列后生成或刷新 `prelogin_capture.xml`
  - 生成内容只保存为运行态资料，不能复制进文档
- 敏感点：Cookie、CSRF 字段、隐藏字段、预登录录包
- 文档规则：只记录字段语义，不记录真实值
- v1 硬规则：预登录未完成时，不允许继续执行验证码提交、SSO 登录或课表拉取

### 3. 验证码处理

- 旧实现位置：`Z:/XKE/core/jw_services.py`
- 关注行为：
  - `capture` 模式依赖录包或人工/开发态捕获流程
  - `coded` 模式依赖动态预登录序列
  - OCR 只作为旧实现参考，不作为文档中的真实样本来源
- 敏感点：验证码图片、OCR 输出、失败响应
- v1 建议：先保留人工/开发态验证码入口，避免把真实验证码图片纳入 fixture

### 4. 登录提交与 portal validate

- 旧实现位置：`JwSsoClient.login_portal`
- 前置条件：`get_login_page` 与 `prepare_prelogin_bootstrap` 已成功
- 关注行为：
  - 提交账号、密码、验证码/加密字段
  - 检查登录失败文案
  - 通过 portal validate 建立后续访问身份
- 成功判据：
  - SSO 登录返回 ticket 跳转
  - 完成跳转后拿到 SSO 侧 TGC
- 失败判据：
  - 登录页缺少 `execution` 或 `login-croypto`
  - 验证码错误
  - 账号密码错误
  - 返回 302 但没有 ticket
  - 门户跳转完成后没有 TGC
- 敏感点：账号密码、Cookie、完整请求头、登录失败响应
- 文档规则：smoke 只写环境变量名，不写真实值

### 5. JW bootstrap

- 旧实现位置：`JwSsoClient.bootstrap_jw_session`
- 前置条件：`login_portal` 成功，且已具备 SSO TGC
- 关注行为：
  - 从 SSO 跳转到 JW
  - 使用 TGC 为 JW service 换取 ticket
  - 访问 JW 主页面确认登录态
  - 校验 `/jsxsd` 路径的 `JSESSIONID`
  - 导出 Cookie bundle
  - 生成 Cookie header
- 成功判据：JW 域名下存在 `/jsxsd` 路径的 `JSESSIONID`
- 失败判据：无法换取 JW ticket，或未拿到 `/jsxsd` 路径登录态 Cookie
- 目标产物：
  - `sso_cookie_bundle.json` 的脱敏结构
  - `jw_cookie_header.txt` 的存在性和更新时机
- 敏感点：真实 Cookie header 和 session 标识
- v1 硬规则：未完成 JW bootstrap 时，不允许请求传统教务课表 HTML

### 6. Cookie 课表拉取

- 旧实现位置：`UnifiedScheduleService.fetch_cookie_schedule`
- 旧解析入口：`parse_cookie_schedule_html`
- 前置条件：JW bootstrap 已成功
- 关注行为：
  - 使用 `cookie_rq`、`term_label`、`academic_term` 定位课表；`cookie_rq` 是课表日期/周次参数，不是 Cookie
  - 请求传统教务课表 HTML
  - 解析周次、星期、节次、课程名、教师、教室、备注
  - 保存 HTML、请求参数和解析结果的脱敏结构
- 失败恢复：
  - 如果课表请求返回登录页或失效页，允许重走完整预登录 + 登录 + JW bootstrap 一次
  - 不允许只复用旧 Cookie 硬刷
- 敏感点：原始 HTML、课程、教师、教室、个人信息
- v1 规则：真实 HTML 不写入文档，测试样本必须脱敏

## v1 状态机

| 状态 | 输入 | 输出 | 失败条件 | 敏感点 |
| --- | --- | --- | --- | --- |
| `NoLocalSession` | `<SESSION_ID>`、本地凭据 | 用户、密码、`prelogin_mode` | session 无效或凭据缺失 | 账号、密码 |
| `PreloginPrepared` | 登录页上下文、`prelogin_mode` | `execution`、加密参数、初始会话 | 登录页字段缺失、录包缺失、预登录序列失败 | 预登录录包、初始 Cookie |
| `PortalAuthenticated` | 账号、密码、验证码/加密字段 | SSO TGC | 验证码错误、账号密码错误、无 ticket、无 TGC | 登录响应、SSO Cookie |
| `JwSessionBootstrapped` | SSO TGC | JW session、`/jsxsd` 登录态 Cookie | 无 JW ticket、无 `/jsxsd` `JSESSIONID` | JW Cookie |
| `CookieScheduleFetched` | JW session、`cookie_rq` | 课表 HTML 与请求参数 | 返回登录页、Cookie 失效、远端异常 | 原始 HTML、请求参数 |
| `JwScheduleCached` | 课表 HTML、解析器 | `jw_schedule` 缓存 | 无有效课程行、解析失败 | 课程、教师、教室 |

### 目标返回语义

`POST /api/schedule/cookie?session_id=<SESSION_ID>` 成功后：

- HTTP 状态：`200`
- `msg`：表达 Cookie 课表刷新成功
- `data.source_key`：`jw_schedule`
- `data.source_type`：`jw`
- `data.source_label`：`教务系统课表`
- `data.data_origin`：`live_fetch`
- `data.cached`：`false`
- `data.rows`：归一化课表行
- `data.term`：包含 `label` 和 `academic_term`
- `data.student`：脱敏或本地 profile 归一化后的学生摘要

失败时应保持现有 API envelope 风格，并返回明确原因：

- 无 session：`401`
- 本地凭据缺失：`401`
- 预登录录包缺失或预登录未完成：`409`
- 传统教务连接未建立或验证码流程未完成：`409`
- 验证码错误或账号密码错误：`401`
- JW ticket 换取失败或未拿到 `/jsxsd` 路径登录态 Cookie：`401` 或 `409`
- 传统教务远端异常：`502` 或当前项目约定的上游错误码
- 课表为空或无法解析：`409`

## 数据落点

### 运行态文件

真实运行态只允许落在本地 runtime/data 体系，不写入文档：

- Cookie bundle：只记录存在性和更新时间
- Cookie header：只记录存在性和更新时间
- 原始课表 HTML：开发态可本地保存，但不能提交真实正文
- 解析结果：保存为 `jw_schedule` 来源的课表缓存

### fixture 规则

后续如需新增 fixture：

- 建议目录：`fixtures/jw/`
- HTML fixture 必须脱敏
- 课程名、教师、教室、学生身份必须替换为假值
- Cookie、token、请求头必须删除或替换为 `<REDACTED>`
- fixture 文件名应体现用途，例如 `cookie_schedule_week_current.redacted.html`

```powershell
Invoke-RestMethod `

  -ContentType "application/json" `
  -Body '{"mode":"current","manual_week":"","cookie_rq":"<YYYY-MM-DD>","term_label":"<TERM_LABEL>","academic_term":"<ACADEMIC_TERM>"}'
```

```powershell

```

## 验收矩阵

| 场景 | 触发方式 | 预期 |
| --- | --- | --- |
| 无 session | 调用 `/api/schedule/cookie` 不带有效 `session_id` | 返回 `401` 或会话过期错误 |
| 本地凭据缺失 | session 存在但 credential store 不存在 | 返回 `401`，提示重新登录 |
| `capture` 缺少预登录录包 | `prelogin_mode=capture` 且本地无可用 `prelogin_capture.xml` | 返回可读 `409`，提示需要先生成或提供预登录录包 |
| `coded` 生成预登录录包 | `prelogin_mode=coded` 执行 Cookie 课表刷新 | 能生成或刷新运行态预登录录包，不把正文写入文档 |
| 只有 Cookie 但无 bootstrap | 手工放置 Cookie 或只有 Cookie header | 判定为未登录，不继续请求课表 |
| 验证码失败 | 传统 SSO 验证码错误 | 返回 `401`，不写入 Cookie 缓存 |
| 登录失败 | 账号或密码错误 | 返回 `401`，不写入课表缓存 |
| JW bootstrap 失败 | 未拿到 `/jsxsd` 路径登录态 Cookie | 不请求课表，返回明确错误 |
| Cookie 失效 | 课表请求返回登录页或失效页 | 重走完整预登录 + 登录 + JW bootstrap 一次；仍失败则返回明确错误 |
| 课表为空 | HTML 可取但无有效课程行 | 返回 `409`，说明课表为空或无法解析 |
| 成功刷新 | Cookie 课表请求成功 | 返回 `source_key=jw_schedule`、`source_type=jw`、`data_origin=live_fetch` |
| 本地读取 | 刷新成功后调用 `/api/schedule/local?source=cookie` | 返回 `data_origin=local_cache` 或等价本地缓存语义 |
| 移动链路回归 | 调用 `/api/schedule/preferred` | 仍走移动教务，不受 Cookie 课表影响 |

## v1 实现顺序

1. 在 `NativeJwScheduleClient.FetchCookieAsync` 建立传统 SSO/JW 登录骨架，不接受外部 Cookie 作为登录入口
2. 从旧 `JwSsoClient` 迁移 `get_login_page`、`prepare_prelogin_bootstrap`、`login_portal`、`bootstrap_jw_session`
3. 先支持 `capture` 和 `coded` 两种预登录模式，并给出缺少录包时的可读错误
4. 实现 JW bootstrap 成功判定：必须拿到 JW 域名下 `/jsxsd` 路径登录态 Cookie
5. 实现 Cookie bundle 与 Cookie header 的运行态保存，不把真实值写入文档或测试
6. 迁移 Cookie 课表 HTML 拉取和 `parse_cookie_schedule_html` 等价解析
7. 在 `ScheduleService.FetchCookieAsync` 保存 `jw_schedule` 归一化数据
8. 补齐 `ScheduleWebHostTests` 中预登录失败、bootstrap 失败、Cookie 成功、Cookie 失效重登和本地缓存读取场景
9. 保持 `course/*` deferred，不引入真实抢课行为
