# JW 协议信息提取研究

日期：2026-10-08。阶段：代码/假样例研究及浏览器辅助的真实页面、请求观察已完成所述范围；纯 C# HTTP 实现与真实采集验收尚未完成。第1至9节保留初轮证据和当时的待核对项，最新事实与实施边界见第10、11节。

## 1. 本轮结论

现有生产链路具备表单认证、Cookie 会话、个人资料和按周课表获取能力。信息模型仍依赖布局位置、文字猜测与历史推算；应先建立页面字段与请求上下文的证据，再冻结学生—学期—周课表文件格式。

协议顺序明确不等于页面字段语义完整。当前研究优先级为：学期/周次目录、个人资料、课程条目与作息；课程编号、校历、调停课只有拿到来源证据后再纳入。继续沿用学校适配器，不扩展多学校框架、通用爬虫或生产浏览器自动化。

## 3. 当前请求链路

~~~text
直接 JW 表单登录
  登录页 -> 验证码 -> 登录 seed -> encoded 表单提交
  -> 已认证 JW 会话
     -> 主页面/个人资料页面 -> 学生资料
     -> 课表首页 -> week 选项、kbjcmsid 模式
     -> 请求 rq + sjmsValue -> 单周课表 HTML
     -> HTML 解析 -> 规范化 -> 本地缓存/API

日常 preferred / 后台刷新
  个人服务 JSON 快照（配置可用时）
  -> 不可用时回退 JW 会话
  -> 统一规范化与缓存入口
~~~

- 本地已初始化账号恢复与远端认证是两件事，研究提取器无需改写本地恢复。
- rq 是教务查询值，不是 Cookie；样例中可为对应周的日期。保留源值，确认日期语义后再生成周一日期。
- sjmsValue 来自首页 kbjcmsid 的 data-value，是课表显示/时间模式参数；确切业务含义需页面及脚本证据，不能直接解释为学期或冬夏作息。
- 当前课表请求没有实现显式学期切换。AcademicTerm/TermLabel 存在于请求模型不能证明历史学期获取已支持。
- 抓取一个周不会取得完整学期课程；available_weeks 是可查询周目录，不能当作已下载周列表。

| 编号 | 当前入口 | 假输入与实际结果 | 意义 |
| --- | --- | --- | --- |
| JW-01 | TraditionalJwClient.ParseStudentProfile | 学院值为空，后面依次是专业/班级：过滤空单元格后，学院变成“专业”、专业变成“班级”、班级丢失 | 保留单元格配对位置；空值不应改变后续字段关联 |

## 7. 提取方案建议

### 页面解析

推荐将现有正则/手写标签平衡逻辑逐步换成单一 HTML DOM 解析依赖，保留学校选择器和少量文本规范化。优先评估 AngleSharp 的纯文档解析与 CSS 选择器；HttpClient 继续负责既有请求、Cookie 和取消逻辑，不引入 JS 引擎或浏览器作为生产依赖。

依据为 AngleSharp 官方仓库 README 的 HTML5 DOM、querySelector/querySelectorAll 与 .NET 支持说明；尚未选择包版本、安装依赖或修改解析器。引用位置：github.com/AngleSharp/AngleSharp。

替换范围限于个人资料、课表首页和课程页面解析，不扩展通用抓取平台。DOM 能处理树结构，字段语义仍必须由当前学校样本和请求证据决定。

### 内部边界

概念上将三个结果分开，具体类型和文件命名留到实施：

1. 学生资料：稳定学号 + 获取到的资料属性；缺失保持缺失，用户覆盖值与源资料独立处理。
2. 学期上下文：已确认学期身份/名称、周目录、可用模式、源请求值。周目录与已缓存周列表分开。
3. 单周课程：学期引用、周号/日期、每次课程的节次数组、名称/教师/教室/源周次文本与明确时间段。

不要用课程名称当唯一 ID；没有源课程标识就先保持独立课程条目，不为多来源自动合并设计复杂 ID 系统。

如果课程只提供跨周范围文字，保留原文；经样本确认后可追加周号数组。不得把一周出现的课程直接扩展为全学期规则。

### 推导信息

来源事实、推导结果和用户设置在职责上分开，先采用文档级来源标记与必要可空字段，不给每个字段增加复杂置信度模型。

例：第5周对应 2026-10-05 周一，可推得第1周周一为 2026-09-07；这只是连续周号假设下的推算，不能标成学校开学日或正式校历。已有明确周目录时优先按目录查找当前周。

更新时间区分本机获取时间与服务器声明的数据时间；重新下载快照不使旧数据变新。选中/查看/当前周是运行时状态，不用作历史文件身份。

### 请求成本

首页和资料按需获取；同次刷新复用首页上下文；只更新用户需要的周。全学期同步只有确认服务能力后显式启动，顺序请求，失败周保留原缓存，不默认后台扫所有学期或页面。

## 10. 真实页面与请求观察（2026-10-08）

用户授权在其 Chrome 会话中研究教务页面，并手动重新登录。浏览器仅为研究工具，不是产品数据获取依赖。本节记录实际页面、脚本和请求的脱敏结论；没有读取浏览器 Cookie/密码/存储或本机凭据，没有执行选课、资料修改或学校数据写入。POST 查询与业务写入不是同一回事。

### 10.2 能提取的核心数据

- 学期页一次返回课程名称、教师、周规则（包含双周）、显式节次数组文本、教学楼、教室及隐藏的学时文字。不同周规则下同一格可以有多门课程。
- .kbcontent 内的 font title 是字段名称，元素文本才是字段值；同格多课以分隔文字/br 连接，需要明确条目边界。
- 同一条跨大节排课规则会在多个格重复展示；同格另有精简/详细/分类展示容器。提取时选一个展示结构，不把视图副本当多门课；也不能按课程名称全局合并不同排课。
- .kbcontent 的 DOM ID 对应行/列/展示模式结构，不能当作课程 ID。无课表课程表有明确课程编号、名称、教师、班级、课程性质/属性；但不能据此声称所有排课条目都已有业务课程编号。
- 无课表课程表和备注是独立来源，不直接变成有确定星期/节次的课程。表名也不证明其中课程在其它表不存在。
- 首页课程有完整 .item-box 与邻接 .box，短标题不能代替完整名称；周页提供学分与星期/周次等信息。
- 两种课表都提供大节作息，明确节次组合与整段时间；没有观察到每小节的官方起止时间，不能固定课间后等分时长。
- 学籍卡片顶部单格内使用“标签：值”，其它行使用标签/值相邻格，存在空值和跨度。学习层次、学制、入学日期应独立识别；不按学号或专业名称猜年级/学历，不把原院系等历史字段误作当前资料。
- 月历给出真实周次/日期对应关系，不等于已取得所有假期、考试或正式校历事件；历史学期周日期目录仍未确认。
- 调停课结果表头含课程编号/名称、教师、班级、开课院系、调课类型、上课周次、调前时间/地点、调整周次、调后周次/时间/地点、调课方式、状态。具体状态含义与有效记录样例待核对，不直接覆盖基础排课。
